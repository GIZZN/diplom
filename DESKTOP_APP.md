# Desktop App — Integration Guide

Базовый URL продакшна: `https://diplom-chi-ten.vercel.app`

---

## 1. Авторизация (pairing flow)

Вход в приложение происходит через браузер — никаких паролей на стороне приложения.

### Шаг 1 — Инициализация

```
POST /api/auth/app/init
Body: {}
```

**Ответ:**
```json
{ "token": "uuid-токен" }
```

Токен живёт **10 минут**, одноразовый.

---

### Шаг 2 — Открыть браузер

Открыть системный браузер (не WebView) по адресу:

```
https://diplom-chi-ten.vercel.app/auth/app?token=<token>
```

Пользователь логинится на сайте (если ещё нет сессии — через форму или Google) и подтверждает вход в приложение.

---

### Шаг 3 — Поллинг

Пока браузер открыт, приложение поллит каждые ~1 секунду с backoff:

```
GET /api/auth/app/check?token=<token>
```

| `status` | Что делать |
|---|---|
| `"pending"` | Продолжать поллинг |
| `"approved"` | Получить JWT и пользователя, прекратить поллинг |
| `"expired"` / HTTP 410 | Показать «Время истекло», предложить войти заново |
| `"invalid"` / HTTP 404 | Игнорировать (уже был использован после `approved`) |
| HTTP 5xx / 429 | Продолжать поллинг с увеличенным интервалом |

**Ответ при `approved`:**
```json
{
  "status": "approved",
  "jwt": "eyJ...",
  "user": {
    "id": "string",
    "name": "string",
    "email": "string",
    "avatar": "url | null",
    "created_at": "ISO"
  }
}
```

Сохранить JWT локально (Keychain / SecureStorage).

## 2. Ревалидация сессии при старте

При каждом запуске приложения — до показа основного интерфейса:

```
GET /api/auth/me
Authorization: Bearer <JWT>
```

| Ответ | Действие |
|---|---|
| **200** | Сессия жива, обновить данные пользователя из `user` в теле |
| **401 / 403** | Сессия истекла / отозвана → очистить JWT, показать экран входа |
| **404 / 5xx / сеть недоступна** | Офлайн-режим — оставить текущую сессию (fail-open) |

**Тело ответа 200:**
```json
{
  "user": {
    "id": 1,
    "name": "string",
    "email": "string",
    "avatar": "url | null",
    "created_at": "ISO",
    "role": "user | admin",
    "plan": "free | pro",
    "pro_expires_at": "ISO | null"
  }
}
```

## 3. Синхронизация сессий

Каждое событие ассистента нужно отправлять на сервер — это данные для аналитики и истории в веб-дашборде.

```
POST /api/desktop/sessions
Authorization: Bearer <JWT>
Content-Type: application/json
```

**Тело:**
```json
{
  "type": "chat_message | live_answer | screen_analysis",
  "question": "string (макс 1000 символов)",
  "answer":   "string (макс 5000 символов)",
  "model":    "string (название модели)",
  "response_time_ms": 1234,
  "tokens_used":      256,
  "session_id": "уникальный ID текущей сессии",
  "created_at": "2026-06-21T10:00:00.000Z"
}
```

| Ответ | Действие |
|---|---|
| **200 / 201** | Успех |
| **401 / 403** | Генерировать событие `auth:expired` → разлогинить, показать экран входа |
| **5xx / сеть** | Поставить в очередь повтора |

> **Важно:** 401 на этом эндпоинте — основной триггер авто-логаута во время работы.

---

## 4. Выход

```
POST /api/auth/logout
Authorization: Bearer <JWT>
Content-Type: application/json
Body: {}
```

Сервер инвалидирует JWT (после этого `/api/auth/me` вернёт 401 по нему).  
Приложение очищает локально сохранённый JWT в любом случае.

---

## 5. CORS (только для dev-сборки)

**Продакшн:** запросы идут через нативный Rust-прокси — CORS не нужен.

**Dev (`npm run dev` / Tauri dev):** фолбэк на `fetch` с `mode: 'cors'`.  
Разрешённые origin'ы уже добавлены на сервере:
- `tauri://localhost`
- `http://localhost:1420`
- `http://localhost:3000`

---

## 6. JWT — формат и декодирование

JWT — стандартный `header.payload.signature` (base64url), подписан RS256/HS256.

**Payload содержит:**
```json
{
  "userId": 1,
  "email": "user@example.com",
  "iat": 1718964000,
  "exp": 1719568800
}
```

Приложение **на клиенте** декодирует `exp` (без проверки подписи) чтобы не делать запрос к `/api/auth/me` с заведомо протухшим токеном. Проверка подписи происходит только на сервере.

```
exp < Date.now() / 1000  →  токен протух локально  →  сразу показать экран входа
```

---

## 7. Проверка плана (опционально)

Поле `plan` в ответе `/api/auth/me`:
- `"free"` — базовый тариф (5 сессий в день)
- `"pro"` — расширенный тариф
- `"pro"` + `pro_expires_at` — Pro на 30 дней, нужно следить за датой

Если хочешь показывать в приложении статус подписки — читай из `user.plan`.

## 8. Чек-лист для реализации

- [ ] `POST /api/auth/app/init` — получить pairing токен
- [ ] Открыть системный браузер с `/auth/app?token=...`
- [ ] `GET /api/auth/app/check?token=...` — поллинг, сохранить JWT при `approved`
- [ ] При старте — `GET /api/auth/me` с Bearer, обработать 401 как разлогин
- [ ] `POST /api/desktop/sessions` — отправлять каждое событие ассистента
- [ ] Обрабатывать 401 на `/api/desktop/sessions` как триггер авто-разлогина
- [ ] `POST /api/auth/logout` — при выходе пользователя
- [ ] Декодировать `exp` из JWT для ранней проверки протухания
- [ ] Очередь повтора для `/api/desktop/sessions` при сетевых ошибках
