# Desktop App — Оплата Pro (Telegram Stars)

Это руководство описывает, **что нужно сделать в десктоп-приложении**, чтобы оплата тарифа Pro
работала с текущей системой API. Делай по плану сверху вниз.

Базовый URL продакшна: `https://diplom-chi-ten.vercel.app`

> Авторизация (pairing), ревалидация сессии и синхронизация сессий описаны в **DESKTOP_APP.md**.
> Здесь — только то, что добавилось/изменилось для **оплаты**.

---

## 0. Что изменилось

- Оплата идёт **только через Telegram Stars** (валюта `XTR`). Карт/других методов нет.
- Тариф «Базовый за 1 звезду» (тест) **удалён**. Остались два тарифа:
  | Тариф | `plan` | Цена | Что даёт |
  |---|---|---|---|
  | Pro на 30 дней | `monthly` | **500 ⭐** | Pro на 30 дней, продление вручную |
  | Pro навсегда | `lifetime` | **2000 ⭐** | Pro навсегда, без продлений |
- Покупка самих звёзд — в боте **@AirStars_Robot**. Это нужно показать пользователю в UI.
- На сайте появилась страница оплаты `/checkout?plan=...` (стиль Stripe). Десктопу она **не обязательна** —
  у приложения уже есть JWT, поэтому проще получить счёт напрямую (см. Вариант A).

## 1. Эндпоинт создания счёта

```
POST /api/payments/create-invoice
Authorization: Bearer <JWT>
Content-Type: application/json

Body: { "plan": "monthly" }   // или "lifetime"
```

**Успех (200):**
```json
{ "url": "https://t.me/invoice/XXXXXXXX" }
```
`url` — это ссылка-инвойс Telegram. Если её открыть, Telegram предложит оплатить звёздами.

**Ошибки:**
| Код | Причина | Действие в приложении |
|---|---|---|
| **401** | JWT нет/протух/отозван | Триггер `auth:expired` → разлогин → экран входа |
| **400** | Неизвестный `plan` | Проверить, что отправляешь `monthly` или `lifetime` |
| **502** | Telegram не отдал инвойс | Показать «Не удалось создать счёт», дать «Повторить» |
| **5xx / сеть** | Сервер/сеть | Показать ошибку, дать «Повторить» |

## 2. Вариант A — рекомендованный для десктопа (прямой инвойс)

У приложения уже есть `JWT`, поэтому браузерный логин не нужен.

**Шаги:**

1. Пользователь жмёт «Перейти на Pro» → выбирает тариф (`monthly` / `lifetime`).
2. `POST /api/payments/create-invoice` с `Bearer <JWT>` и `{ plan }`.
3. Получив `{ url }` — **открыть его в системном браузере** (Telegram перехватит ссылку и откроет счёт).
   - Если у пользователя нет звёзд — показать рядом кнопку **«Купить звёзды» → `https://t.me/AirStars_Robot`**.
4. После открытия счёта приложение показывает статус **«Ожидаем оплату…»** и запускает поллинг (раздел 4).
5. Когда `plan` стал `pro` — закрыть статус, разблокировать Pro, обновить UI.

**Псевдокод:**
```ts
async function buyPro(plan: "monthly" | "lifetime") {
  const res = await api.post("/api/payments/create-invoice", { plan }); // с Bearer JWT
  if (res.status === 401) return onAuthExpired();
  if (!res.ok || !res.data.url) return showError("Не удалось создать счёт");

  openInSystemBrowser(res.data.url);   // НЕ во встроенном WebView
  showWaitingForPayment();             // спиннер + текст про @AirStars_Robot
  startPlanPolling();                  // см. раздел 4
}
```

> Важно: открывать `url` именно во **внешнем браузере / через ОС** (`shell.open` в Tauri,
> `open` в Electron). Telegram-ссылки не работают во встроенном WebView.

## 3. Вариант B — открыть веб-страницу оплаты (опционально)

Если хочешь переиспользовать готовую Stripe-подобную страницу с подсказками:

```
openInSystemBrowser("https://diplom-chi-ten.vercel.app/checkout?plan=monthly")
```

Особенность: страница работает по **cookie-сессии браузера**, а не по JWT приложения.
Если в браузере пользователь не залогинен — его перекинет на `/auth?redirect=/checkout?...`,
он войдёт и попадёт обратно на оплату. Это лишний шаг логина, поэтому для приложения
**предпочтительнее Вариант A**. Дальнейшее определение успеха — тот же поллинг (раздел 4).

## 4. Определение успешной оплаты (поллинг `/api/auth/me`)

Отдельного «успех»-вебхука для приложения нет. Факт оплаты определяем по смене плана.
После того как открыли счёт:

```
GET /api/auth/me
Authorization: Bearer <JWT>
```

- Поллить **каждые 3 секунды**, максимум ~2 минуты (≈40 попыток).
- Как только `user.plan === "pro"` → **оплата прошла**:
  - остановить поллинг,
  - разблокировать Pro-функции,
  - обновить данные пользователя из ответа.
- Если за 2 минуты план не сменился — остановить поллинг, оставить кнопку «Проверить ещё раз».
  (Пользователь мог отвлечься или ещё не купил звёзды — это нормально.)

**Псевдокод:**
```ts
function startPlanPolling() {
  let tries = 0;
  const id = setInterval(async () => {
    if (++tries > 40) { clearInterval(id); showCheckAgain(); return; }
    const me = await api.get("/api/auth/me"); // Bearer JWT
    if (me.ok && me.data.user.plan === "pro") {
      clearInterval(id);
      onProUnlocked(me.data.user);  // обновить состояние + UI
    }
  }, 3000);
}
```

Тело ответа `/api/auth/me` (см. DESKTOP_APP.md, раздел 2):
```json
{ "user": { "plan": "free | pro", "pro_expires_at": "ISO | null", ... } }
```

## 5. Гейтинг Pro-функций

Источник правды о тарифе — поле `user.plan` из `/api/auth/me`. Не храни «куплено» только локально.

- `plan === "free"` → ограничения базового тарифа (5 сессий в день и т.д.).
- `plan === "pro"` → полный доступ.
- `plan === "pro"` + `pro_expires_at` (для `monthly`) → следить за датой:
  по истечении сервер сам сбросит в `free` при следующем `/api/auth/me`
  (ленивый даунгрейд). Поэтому **перечитывай план при старте и периодически**.
- `lifetime` приходит как `plan === "pro"` с `pro_expires_at === null`.

Рекомендация: перечитывать `/api/auth/me` при запуске приложения и, например, раз в N минут,
чтобы UI отражал актуальный тариф и истечение Pro.

## 9. Быстрый сценарий «happy path»

1. Пользователь в приложении жмёт **Pro → Pro на 30 дней**.
2. Приложение: `POST /api/payments/create-invoice {plan:"monthly"}` → `{url}`.
3. Приложение открывает `url` → Telegram показывает счёт на **500 ⭐**.
4. Пользователь подтверждает (звёзды есть; если нет — покупает в **@AirStars_Robot**).
5. Telegram проводит платёж → сервер (webhook) ставит `plan = pro`, `pro_expires_at = +30 дней`.
6. Поллинг приложения видит `plan === "pro"` → показывает «Готово», разблокирует Pro.
