# Desktop App — Тариф: отображение плана и переход к оплате

Десктоп — **конечный продукт и тонкий клиент** (модель как в IDE с ИИ, например Cursor):
он только **дёргает эндпоинты, принимает и отображает данные**. Всё «тяжёлое» и
чувствительное — авторизация и оплата — живёт **только в вебе**.

Базовый URL продакшна: `https://diplom-chi-ten.vercel.app`

> Pairing-авторизация, ревалидация сессии и синхронизация сессий — в **DESKTOP_APP.md**.
> Здесь — про **тариф**: как десктоп показывает план и срок, и как уводит пользователя на оплату в веб.

---

## 0. Принцип разделения (важно)

| Делает **веб** (чувствительное, только там) | Делает **десктоп** (тонкий клиент) |
|---|---|
| Авторизация / логин / Google / OTP | Открывает веб для входа (pairing), хранит выданный JWT |
| Создание счёта, оплата Telegram Stars, webhook | Открывает веб-страницу оплаты в браузере |
| Запись плана в БД, продление, истечение | **Читает** `plan` и `pro_expires_at`, **отображает** план и остаток времени |

**Десктоп НЕ должен:**
- ❌ вызывать `POST /api/payments/create-invoice` и любые платёжные ручки;
- ❌ работать со звёздами / инвойсами / Telegram-оплатой внутри приложения;
- ❌ считать план «купленным» локально и хранить это как истину;
- ❌ менять/продлевать тариф сам.

**Десктоп ДОЛЖЕН:**
- ✅ авторизоваться через веб-реквест (pairing, см. DESKTOP_APP.md);
- ✅ получать тариф только из `GET /api/auth/me`;
- ✅ показывать корректный **остаток времени до конца плана** и **сам план**;
- ✅ для апгрейда — открывать веб в системном браузере.

## 1. Эндпоинты, которые использует десктоп

Только **чтение** + авторизация. Платёжных ручек здесь нет намеренно.

| Эндпоинт | Назначение |
|---|---|
| `POST /api/auth/app/init` + `GET /api/auth/app/check` | Pairing-вход через веб (DESKTOP_APP.md) |
| `GET /api/auth/me` (Bearer JWT) | **Единственный источник** тарифа: `plan`, `pro_expires_at` |
| `POST /api/auth/logout` | Выход |
| `POST /api/desktop/sessions` (Bearer JWT) | Синхронизация событий ассистента (DESKTOP_APP.md) |

Апгрейд — это не эндпоинт, а **открытие веб-страницы** в браузере (раздел 3).

## 2. Отображение плана и остатка времени

Источник правды — ответ `GET /api/auth/me`:

```json
{ "user": { "plan": "free | pro", "pro_expires_at": "ISO | null", ... } }
```

Логика отображения:

| `plan` | `pro_expires_at` | Что показать |
|---|---|---|
| `free`| — | «Free» (базовый тариф) |
| `pro` | `null` | «Pro · навсегда» (lifetime) |
| `pro` | ISO в будущем | «Pro · осталось N дней» (см. формат ниже) |
| `pro` | ISO в прошлом | Считать истёкшим → показать «Free». Сервер сам сбросит план при следующем `/api/auth/me` (ленивый даунгрейд) |

**Расчёт остатка (псевдокод):**
```ts
function planBadge(user) {
  if (user.plan !== "pro") return { label: "Free", expires: null };
  if (!user.pro_expires_at) return { label: "Pro · навсегда", expires: null };

  const ms = new Date(user.pro_expires_at).getTime() - Date.now();
  if (ms <= 0) return { label: "Free", expires: null }; // истёк, ждём даунгрейд на сервере

  const days = Math.floor(ms / 86_400_000);
  const hours = Math.floor((ms % 86_400_000) / 3_600_000);
  const left = days >= 1 ? `${days} дн.` : `${hours} ч.`;
  return { label: `Pro · осталось ${left}`, expires: user.pro_expires_at };
}
```

**Правила, чтобы время было «корректным»:**
- `pro_expires_at` приходит в **ISO/UTC** — парсить как дату, сравнивать с `Date.now()`. Не считать остаток от локально кешированных значений.
- **Перечитывать `/api/auth/me`:** при старте приложения, при фокусе окна и периодически (например, раз в 5–10 мин), чтобы бейдж и остаток были актуальны и вовремя показали истечение.
- Сам отсчёт в UI можно тикать локально (раз в минуту), но «правду» о дате брать с сервера.
- Не блокировать оффлайн жёстко: если `/api/auth/me` недоступен — показать последнее известное состояние (как в DESKTOP_APP.md, fail-open).

## 3. Переход к оплате (апгрейд) — через веб

Кнопка «Перейти на Pro» в десктопе **не платит сама**, а открывает веб-страницу оплаты
в системном браузере (как Cursor открывает биллинг в браузере):

```ts
function openUpgrade(plan /* "monthly" | "lifetime" */) {
  openInSystemBrowser(`https://diplom-chi-ten.vercel.app/checkout?plan=${plan}`);
  // дальше — см. раздел 4: после возврата перечитать /api/auth/me
}
```

- Открывать **во внешнем браузере** (`shell.open` в Tauri / `shell.openExternal` в Electron), **не во встроенном WebView** — там работает веб-сессия, Telegram-оплата и т.д.
- Если в браузере нет веб-сессии — веб сам уведёт на `/auth?redirect=/checkout?...`, пользователь войдёт и вернётся к оплате. Десктопу об этом думать не нужно.
- Всё, что связано со звёздами и счётом (включая подсказку про бота **@AirStars_Robot**), показывает **веб-страница оплаты**. В десктопе это дублировать не нужно.

## 4. Обновление статуса после оплаты

Оплата происходит в браузере, поэтому десктоп узнаёт о новом плане только перечитав `/api/auth/me`.

- После `openUpgrade(...)` запусти **лёгкий поллинг** `GET /api/auth/me` каждые 3–5 c (до ~2 мин)
  и/или перечитай при возврате фокуса на окно приложения.
- Как только `user.plan === "pro"` (а для `monthly` — ещё и обновился `pro_expires_at`) →
  обнови бейдж/остаток и покажи «Pro активен».
- Если за ~2 мин ничего не изменилось — останови поллинг, оставь кнопку «Обновить статус»
  (пользователь мог не закончить оплату). Это нормально.

```ts
async function refreshAfterUpgrade() {
  let tries = 0;
  const id = setInterval(async () => {
    if (++tries > 30) { clearInterval(id); return; }
    const me = await api.get("/api/auth/me"); // Bearer JWT
    if (me.ok && me.data.user.plan === "pro") {
      clearInterval(id);
      updatePlanUI(me.data.user); // см. planBadge()
    }
  }, 4000);
}
```

## 5. Обработка ошибок и сессии

| Ситуация | Действие десктопа |
|---|---|
| `401/403` на `/api/auth/me` или `/api/desktop/sessions` | `auth:expired` → очистить JWT → экран входа (pairing) |
| `/api/auth/me` недоступен (5xx/сеть) | Оффлайн: показать последнее известное состояние плана |
| Локально `exp` из JWT уже в прошлом | Сразу экран входа, не дёргать сервер (DESKTOP_APP.md, раздел 6) |

## 6. Чек-лист реализации

- [ ] Тариф берётся **только** из `GET /api/auth/me` (`plan`, `pro_expires_at`), не из локального кеша как истины
- [ ] Бейдж плана: Free / Pro · навсегда / Pro · осталось N
- [ ] Корректный расчёт остатка от `pro_expires_at` (UTC), с обработкой истечения
- [ ] Перечитывание `/api/auth/me` при старте, при фокусе окна и периодически
- [ ] Кнопка «Перейти на Pro» открывает `…/checkout?plan=…` во **внешнем браузере**
- [ ] После апгрейда — поллинг/refresh `/api/auth/me`, обновление UI при `plan === "pro"`
- [ ] Никаких платёжных вызовов и работы со звёздами в десктопе
- [ ] `401` на read-эндпоинтах → авто-разлогин (pairing заново)
- [ ] Оффлайн fail-open: показывать последнее известное состояние

---

## 7. Happy path

1. Десктоп при старте: `GET /api/auth/me` → рисует бейдж «Free» или «Pro · осталось N».
2. Пользователь жмёт **«Перейти на Pro»** → десктоп открывает `…/checkout?plan=monthly` в браузере.
3. Веб делает всё: логин (если надо) + оплата Telegram Stars. Десктоп ждёт.
4. Десктоп поллит `/api/auth/me`, видит `plan === "pro"` + `pro_expires_at` → показывает «Pro · осталось 30 дн.».
5. Дальше десктоп просто периодически перечитывает `/api/auth/me`, чтобы остаток времени оставался корректным.
